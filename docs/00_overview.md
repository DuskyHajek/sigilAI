# Supernova Dashboard — Overview
### What it is, what it does, and why we built it this way

---

## What this dashboard is

A thesis-aware investment intelligence tool built specifically for the Sigil Supernova fund. Not a generic news aggregator, not a stock screener, not a Bloomberg terminal lite. A tool that reads the world through one specific investment framework and surfaces only what matters — filtered, scored, and explained in the fund's own language.

The demo goal: show that you understood the Sigil memo well enough to encode it as software.

---

## Three panels

### Panel 1 — Theme Pulse Heatmap

Live activity score for each of the 7 Sigil themes. For every theme the dashboard shows how much news is flowing today and whether that news is bullish or bearish for the thesis. At a glance you can see which themes are active and which are quiet, without reading a single article.

### Panel 2 — Watchlist Intelligence

20 curated stocks across all 7 themes. Each card shows live price, 30-day change, and a **SIGIL AI insight line** — one sentence explaining what happened this week through the thesis lens specifically. This is the core value. Anyone can see SK Hynix is up 9.8%. The SIGIL AI line explains why it matters for the HBM memory bottleneck thesis.

### Panel 3 — Weekly Brief

A 3–4 sentence analyst brief generated by Claude with the full Sigil thesis as its context. It names the single most important development of the week, adds one secondary signal worth watching, and acknowledges one counter-thesis risk. Written like a CIO morning note, not a chatbot summary.

## APIs used

### Anthropic Claude API
The intelligence layer. Used for everything that requires judgment:
- Classifying each news article by theme and sentiment
- Scoring each theme's daily pulse (activity + thesis alignment)
- Generating the SIGIL AI stock insight line per ticker
- Writing the weekly brief

Model: `claude-sonnet-4-20250514`. The Sigil investment thesis is baked into the system prompt — so every output is evaluated against their specific framework, not generic financial logic.

### NewsAPI.org
Fetches fresh headlines for each of the 7 themes using 10 curated search keywords per theme. Free tier gives 100 requests per day — more than enough for a manual sync workflow. Keywords are defined in `config/thesis.js` and can be updated without touching any other code.

### Yahoo Finance (unofficial)
Live stock prices and 30-day change for all 20 watchlist tickers. No API key needed. Used via the `yahoo-finance2` npm package. Fast, free, reliable enough for a demo.

### Internal cache (`cache.json`)
Not really an API — but worth naming explicitly. Every sync result is written to a flat JSON file on the backend. The dashboard loads instantly from cache on every page load. No API calls fire until the user clicks Sync Engine.

---

## Backend routes (3 only)

| Method | Route | What it does |
|---|---|---|
| `GET` | `/api/health` | Returns status, mode (live vs mock), and last sync timestamp. Used by the header to show the LIVE / OFFLINE indicator. |
| `GET` | `/api/dashboard` | Returns the full cached payload: all 7 theme pulse scores, all 20 watchlist tickers with prices and insights, and the weekly brief. Served instantly from cache — no API calls. |
| `POST` | `/api/sync` | Manual full refresh. Fetches news → classifies with Claude → fetches prices → generates stock context lines → scores theme pulses → generates weekly brief → writes cache → returns updated dashboard data. Triggered only by the Sync Engine button. |

No cron jobs. No background refresh. The user syncs when they want fresh data.

## What this actually achieves

**Signal vs noise, filtered to the thesis.** Every article is evaluated against the specific Sigil Supernova framework. The AI knows the 7 themes, the investment logic, the bull and bear signals for each. Irrelevant news is ignored. Relevant news is scored and explained in thesis-specific language — not generic financial commentary.

**Context on top of price data.** Anyone can see a stock moved. The SIGIL AI line explains why it matters for the specific thesis angle that stock represents. That layer of interpretation is what saves an analyst 30 minutes of reading every morning — and it's something a Bloomberg terminal cannot generate.

**An automated analyst brief.** The weekly brief synthesises everything across all 7 themes into a paragraph a CIO would actually read. It takes a position. It names the most important development. It acknowledges counter-signals. It sounds like a sharp analyst talking to a colleague.

**Proof of concept for the application.** In one URL, this demonstrates: you understood the Sigil memo deeply enough to encode it as software, you can build AI tools that streamline real investment workflow, and you think about what is actually useful rather than what looks impressive. That is the thing that gets you the interview.

## Design decisions worth noting

**Manual sync, no crons.** Crons add cost, complexity, and the risk of a job firing at the wrong moment. A Sync Engine button is more transparent, more controllable, and more impressive to demo live.

**20 tickers, not 51.** A focused watchlist signals curation and intent. 51 tickers looks like a screener. 20 well-chosen stocks across 7 themes looks like an analyst built it.

**3 routes, not 6.** The extra endpoints in earlier drafts were architecture for architecture's sake. Three routes cover everything the frontend needs.

**Prompts in one file.** All Claude prompts live in `services/prompts.js`. Nothing is written inline in service or route files. This means prompt tuning — which is ongoing — never requires touching application logic.

**Config as single source of truth.** Theme descriptions, keywords, tickers, colors, and bull/bear signals all live in `config/thesis.js`. Change something there and it propagates everywhere: the AI system prompt, the news search, the watchlist, the frontend colors. Nothing is hardcoded in two places.
